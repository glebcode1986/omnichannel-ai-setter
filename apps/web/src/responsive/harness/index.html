Does the console fit the widths it claims to support?

Each width below gets its own iframe loading surfaces.html, which renders the real shell and the real stylesheet around the worst case each surface has to survive — one token with no break opportunity in it. An iframe is used rather than one resizable container because media queries read a viewport, not a parent element: a container set to 375px still gets the desktop rules.

Document overflow is documentElement.scrollWidth − clientWidth inside the frame: anything above zero means the page itself scrolls sideways, which is the failure this measures. Surface overflow is each surface's own scrollWidth against the width of the main column it sits in; a surface may exceed it only if it declares a scroll boundary of its own, and the last column says whether it does.
